# Оптимизация задержки, 7 октября 2026

На RTX 4060 и Intel Core i5-14400F обработка области стала примерно на 40% быстрее в парных проверках на исходных скриншотах. Это измерение обработки изображения, не гарантированная задержка выстрела в игре.

## Измерения

Сравнивались предыдущий EXE и новая версия последовательно, с одинаковой областью 640×640, на двух исходных изображениях. Для каждого изображения — три парных повтора по 200 вызовов после прогрева модели. Кликов не было.

| Этап | Предыдущая версия | Новая версия |
|---|---:|---:|
| Подготовка + модель + решение, медианы серий | 2.85–2.97 мс | 1.69–1.92 мс |
| Подготовка + модель + решение, p95 серий | 5.36–5.77 мс | 3.83–4.07 мс |
| Подготовка входа, медианы новой версии | — | 0.16–0.23 мс |
| Модель и обмен тензорами, медианы серий | 1.77–1.87 мс | 1.52–1.64 мс |
| Захват рабочего стола + обработка, медиана 30 кадров | 3.63 мс | 2.49 мс |
| Захват рабочего стола + обработка, p95 30 кадров | 4.36 мс | 2.56 мс |

Снижение медианы в шести парных сериях: 32.7–42.8%. Настройки GPU, планировщик Windows и нагрузка игры влияют на задержки. Проверка рабочего стола не заменяет измерение от появления персонажа до фактического выстрела CS2.

## Что изменилось

- Область захвата по умолчанию уменьшена с 960×960 до 640×640: на CPU копируется на 56% меньше пикселей. Вход модели остаётся 320×320.
- В `person-seg-fast-320.onnx` вычисление маски в центре перенесено в граф ONNX. На CPU возвращается один тензор `[1,7,2100]`: координаты рамок, оценка person, максимальная оценка другого класса и логит маски в центре. Вместо 448400 float возвращаются 14700 float: около 59 КБ вместо 1.79 МБ, в 30.5 раза меньше.
- Веса YOLO сохранены. NMS и порог маски остались; модель не квантизировалась. Полная модель сохранена для создания диагностических картинок.
- Подготовка RGB/CHW выполняется векторными инструкциями AVX2 с кешированными координатами билинейной выборки. CPU без AVX2 автоматически использует обычный вариант; `--no-avx2` позволяет проверить его вручную.
- В активном режиме вместо обычного Sleep используется таймер высокой точности с целевым ожиданием 0.2 мс. Это запрошенное ожидание, не гарантия времени пробуждения Windows. Неактивное окно продолжает ждать без частого опроса.
- Захват подготавливается при F8, до первого удержания Mouse4. Дополнительная искусственная задержка перед первым нажатием не добавлена.

## Проверка качества

Пять исходных положительных/отрицательных проверок проходят на ROI 640 и 960. Дополнительно выполнено 40 проверок соответствия результатов: полная/компактная модель, AVX2/обычная подготовка, обе области захвата. Решения совпали; напечатанные оценки совпали с допуском 0.002. Профиль компактной модели содержит DmlExecutionProvider без CPU execution provider.

Область 320×320 проверялась и дала ложное срабатывание в выбранной точке между ногами. Поэтому она не выбрана по умолчанию. 640×640 прошла имеющиеся проверки, но на других кадрах тоже может ухудшить распознавание из-за потери контекста. Для прежнего размера: `--roi 960`.

Данные из пяти изображений недостаточны для общей оценки точности на всех моделях/картах/расстояниях. Истинные хитбоксы игры по-прежнему не считываются.

## Запуск

Скачать и полностью распаковать обновлённый `gpu-trigger-portable.zip`, затем запустить `run-live.cmd`. Основной проект обновлён в `E:\projects\gpu-trigger`.

Для запуска из проекта:

```powershell
& "E:\projects\gpu-trigger\gpu-trigger.exe" --live
```

Прежняя область захвата:

```powershell
& "E:\projects\gpu-trigger\gpu-trigger.exe" --live --roi 960
```

Повторная генерация компактной модели: `tools/optimize_model.py` после экспорта исходной модели. Повторная сборка программы: `build.cmd`. Сборка portable ZIP: `tools/build_portable.ps1`. Проверка соответствия: `run-tests.ps1 -Extended`.

Интервал `--cooldown-ms 100` ограничивает повторные нажатия и не задерживает первое срабатывание. Удержание ЛКМ `--hold-ms 8` также начинается после решения модели, без ожидания перед нажатием.
