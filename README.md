# GPU person trigger — экспериментальная версия

Программа на C++ распознаёт видимый силуэт человека возле центра игрового окна. Это не детектор внутренних хитбоксов CS2. Команды персонажей не различаются.

## Последняя сборка: TensorRT и подготовка на GPU

Готовый **gpu-trigger-portable.zip** обновлён. Полностью распакуйте архив, запустите
`run-live.cmd`. F8 — привязать окно, удерживать Mouse4 — разрешить реакцию, F10 — выход.
`run-dry.cmd` запускает проверку без кликов. На RTX 4060 в строке запуска ожидается
`Provider: TensorRT FP16`. CUDA Toolkit и Python устанавливать не требуется.

Парные проверки: обработка области **1.74–1.77 → 0.95–0.97 мс**, примерно на 45%
быстрее. Это медиана обработки, не гарантированное время до выстрела в игре.
Подробности и ограничения: [diagnostics/latency-rtx4060.md](diagnostics/latency-rtx4060.md).

Сохранены вход 320×320, ROI 640 и логика распознавания. 150 вариантов имеющихся
изображений прошли сравнение решений с исходной FP32-моделью без расхождений.
Новые игровые сцены всё ещё требуют проверки; FP16 немного меняет оценки модели.

TensorRT-движок собран для RTX 4060. При несовместимости программа автоматически
выбирает DirectML FP16. `run-directml.cmd` принудительно выбирает DirectML;
`run-compatible.cmd` дополнительно включает старый путь через CPU (например, при
разных GPU для монитора и модели). `--no-sync-spin` уменьшает нагрузку CPU ценой задержки.
`--model` и `--preview` используют DirectML. Полные диагностические маски относятся
к сохранённой FP32-модели, а не к точному FP16-результату TensorRT.

Повторить проверку меняющихся кадров без ввода: `gpu-trigger.exe --validate tests`.
Предыдущие разделы ниже описывают историю проекта и старые замеры.

Используется YOLOv8n-seg, обученная на COCO, экспортированная в ONNX с фиксированным входом 320×320. Вычисления модели выполняются через ONNX Runtime DirectML на GPU. Подготовка входного изображения и проверка маски выполняются на CPU. Python для запуска готовой программы не нужен.

## Запуск в PowerShell

Проверка распознавания без нажатий мыши:

```powershell
& "E:\projects\gpu-trigger\gpu-trigger.exe"
```

Запуск с нажатиями ЛКМ:

```powershell
& "E:\projects\gpu-trigger\gpu-trigger.exe" --live
```

После загрузки модели переключись в CS2 и нажми F8: программа запомнит активное окно. Для распознавания удерживай Mouse4, первую боковую кнопку. В режиме LIVE нажатие ЛКМ начинается, когда центр окна попадает в маску человека. Если Mouse4 отпущена или фокус ушёл в другое окно, новые нажатия не отправляются. F8 отключает реакцию; F10 завершает программу. В DRY RUN выводится результат распознавания, но мышь не нажимается.

Не перемещай EXE отдельно: модель и DLL должны оставаться рядом с ним. Модель ищется относительно EXE, поэтому команда работает из любой папки. При выключении/смене режима монитора захват может потерять доступ: программа отключится; снова нажми F8 в игре. Для начала используй полноэкранный оконный режим. Поддерживается обычная ориентация монитора без поворота.

## Что означает вывод

- `center=1`: центр попал в распознанную маску; `center=0`: не попал.
- `conf`: оценка класса person; `mask`: оценка принадлежности точки к маске. Это оценки модели, а не измеренная вероятность правильного попадания.
- `inference_ms`: время обработки моделью, включая передачу тензоров.
- `pipeline_ms`: захват, подготовка входа, модель и проверка результата.
- `frame_age_ms`: возраст полученного кадра после распознавания.
- `hits`: число обработанных кадров с попаданием центра в маску; это не количество кликов.
- `clicks`: количество реально отправленных нажатий ЛКМ. В DRY RUN всегда 0.
- `stale`: отброшенные старые кадры. Такой результат не вызывает клик.

## Оптимизация

Desktop Duplication получает кадры через Direct3D 11. На CPU считывается только квадрат возле прицела, по умолчанию 640×640, затем он уменьшается до 320×320. Полный экран не копируется в память CPU. Входной и выходные тензоры выделяются один раз. Модель прогревается до включения реакции. Обработка идёт без очереди кадров; повторно обрабатывать один захваченный кадр программа не будет. Полные маски персонажей в рабочем цикле не строятся: проверяются четыре соседние точки прототипа маски. Вывод в консоль ограничен двумя сообщениями в секунду.

Параметры:

| Параметр | По умолчанию | Значение |
|---|---:|---|
| `--confidence` | 0.45 | Порог класса person. Снижение повышает и чувствительность, и риск ошибок. |
| `--roi` | 640 | Сторона захватываемой области в физических пикселях. Малый квадрат может обрезать близкого персонажа и ухудшить распознавание. |
| `--device` | 0 | Индекс GPU в DXGI. На проверенном компьютере это RTX 4060. |
| `--cooldown-ms` | 100 | Минимальный интервал между повторными нажатиями. Первый клик не ждёт этот интервал. |
| `--hold-ms` | 8 | Длительность нажатия. Отпускание выполняется отдельным событием; рабочий цикл продолжает проверять управление. |
| `--max-age-ms` | 40 | Предельный возраст кадра для срабатывания. |

Пример уменьшения интервала повторных нажатий:

```powershell
& "E:\projects\gpu-trigger\gpu-trigger.exe" --live --cooldown-ms 60
```

## Проверки исходной версии 7 октября 2026

Компьютер: NVIDIA RTX 4060, Intel Core i5-14400F. C++17, MSVC, `/O2`, `/W4 /WX`. Сборка без предупреждений. ONNX Runtime 1.24.4 и DirectML 1.15.4. Профиль ONNX Runtime показал `DmlExecutionProvider` у вычислительного узла модели; узлов с CPU execution provider в этом профиле не было.

| Проверка | Результат |
|---|---|
| Исходный скриншот с близким персонажем | Центр внутри маски; оценка класса 0.891 |
| Исходный скриншот с группой персонажей | Центр внутри маски; оценка класса 0.567 |
| Область стены | Центр вне маски |
| Пустой участок над персонажами | Центр вне маски |
| Выбранная точка в промежутке между ногами | Центр вне маски |

После прогрева, 100 повторений на первом скриншоте: модель — медиана 2.096 мс, p95 2.671 мс; подготовка входа + модель + решение — медиана 3.259 мс, p95 4.038 мс. Второй скриншот: модель — медиана 1.948 мс, p95 2.409 мс; вся обработка области — медиана 3.046 мс, p95 3.578 мс.

Проверка захвата рабочего стола на 10 свежих кадрах: захват + подготовка + модель + решение — медиана 4.088 мс, p95 4.389 мс. В этой проверке клики не отправлялись. Эти значения не включают ожидание нового игрового кадра, обработку ввода игрой и её нагрузку на GPU. Скорость и фактическое срабатывание в запущенной CS2 пока не проверены.

Повторить проверки картинок без кликов:

```powershell
& "E:\projects\gpu-trigger\run-tests.ps1"
```

Создать диагностическую картинку с масками:

```powershell
& "E:\projects\gpu-trigger\gpu-trigger.exe" --image "C:\путь\скриншот.png" --preview "C:\путь\маски.png" --benchmark 100
```

Зелёная область на `example-1-mask.png` и `example-2-mask.png` — маска человека. Красный крест — проверяемая точка. `example-gap-mask.png` показывает отрицательную проверку между ногами. Полные маски рисуются только для диагностических файлов, не в игровом цикле.

## Ограничения

Два скриншота и три выбранных участка — маленькая проверка, не оценка общей точности. Модель обучена на обычных фотографиях, не на CS2. Она может пропускать руки/ноги, путать фон с человеком, включать оружие в силуэт или распознавать руки самого игрока. Дальние, частично закрытые и быстро движущиеся персонажи не проверены. Модель не имеет доступа к хитбоксам, глубине сцены или состоянию оружия. Для повышения точности нужны дополнительные кадры CS2 и дообучение сегментации; увеличение частоты обработки не исправляет ошибки модели.

## Исходники и зависимости

`main.cpp` — программа; `build.cmd` — повторная сборка с установленной на этом компьютере Visual Studio. Заголовки в `sdk/include`, библиотека `onnxruntime.lib`, DLL и модель включены. Лицензии зависимостей сохранены в `licenses/`. Ultralytics и её модель используют AGPL-3.0; при дальнейшем распространении учитывай её условия.

Модель получена из официальных весов `https://github.com/ultralytics/assets/releases/download/v8.3.0/yolov8n-seg.pt` и экспортирована с ultralytics 8.3.235, ONNX 1.19.1, opset 17, статическим входом 320, без встроенного NMS. Подавление дубликатов реализовано в C++.

Документация: [DirectML execution provider](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html), [YOLOv8 и сегментация](https://huggingface.co/Ultralytics/YOLOv8), [Desktop Duplication](https://learn.microsoft.com/en-us/windows/win32/direct3ddxgi/desktop-dup-api).

Исходные веса модели сохранены в models/yolov8n-seg.pt. Скрипт повторного экспорта — tools/export_model.py; зависимости Python — tools/requirements.txt. Готовая программа не требует Python. Временное окружение для экспорта из старой рабочей папки не переносилось.

## Текущая оптимизированная версия

Область захвата по умолчанию — 640×640. Используется person-seg-fast-320.onnx с вычислением маски в точке прицела на GPU и компактным выходом. Подготовка RGB/CHW ускорена AVX2; CPU без AVX2 поддерживаются автоматически. Полная модель person-seg-320.onnx выбирается автоматически для --preview.

Парные проверки на RTX 4060: обработка области 2.85–2.97 мс в исходной версии и 1.69–1.92 мс в текущей (медианы серий). Захват рабочего стола + обработка: 3.63 → 2.49 мс. Это не измерение от появления цели до выстрела игры. Подробности, ограничения и p95: diagnostics/latency-results.md; исходные результаты: diagnostics/latency-comparison.txt.

Обновлённый gpu-trigger-portable.zip содержит текущую сборку и обе модели. Полностью распаковать и запустить run-live.cmd. Прежний standalone EXE оптимизации не содержит; его сборщик обновлён для включения новой модели при будущей сборке.

Для прежнего размера области: --roi 960. ROI 320 дал ложное срабатывание между ногами в имеющемся тесте и не рекомендуется. Для резервной подготовки: --no-avx2. Повторная проверка вариантов: run-tests.ps1 -Extended (40 проверок соответствия и 5 исходных проверок).

Повторная сборка: build.cmd. Повторная генерация моделей: tools/export_model.py (автоматически вызывает tools/optimize_model.py). Пересборка portable ZIP: tools/build_portable.ps1. Таймер активного опроса запрашивает 0.2 мс; планировщик Windows может пробудить поток позже. Интервал повторных нажатий 100 мс не задерживает первое нажатие.

Новая папка portable и ZIP были проверены Microsoft Defender без зарегистрированных обнаружений для этих путей. Защита не отключалась; отсутствие обнаружений сейчас не гарантирует будущие результаты.
